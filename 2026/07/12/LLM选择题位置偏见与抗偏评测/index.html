模型做选择题为什么总偏爱 A？

从选项轮换、语义作答到 PriDe 和 SCOPE，构建可审计的 LLM 选择题抗偏评测流程

发布于 2026.07.12 更新于 2026.08.12 约 5 分钟

在使用选择题评测大语言模型时，我遇到过一个很容易被忽略的现象：同一道题只改变选项顺序，模型就可能给出不同答案；当正确答案位于 A 时，成绩甚至可能显著更高。

这意味着最终分数混合了两类因素：模型是否真正理解知识，以及它是否偏爱某个选项标签或位置。

因此，可靠的选择题评测既不能只跑一次固定顺序，也不能只依赖一句「不要受选项位置影响」的 Prompt。

一、位置偏见如何污染结果

如果模型真正理解题目，三个版本指向的语义答案应当一致。但在实际测试中，模型可能表现出：

  • 偏好特定字母或编号；
  • 对靠前选项给予更高概率；
  • 选项重排后推理过程也随之变化；
  • 输出文字解释正确，却返回了错误字母；
  • 自报置信度很高，但不同排列之间不稳定。

ICLR 2024 的 PriDe 论文将这类现象称为 selection bias，并通过置换选项内容，估计模型对 option ID 的先验偏好。

二、最低成本的基础检查

在引入复杂校正之前，可以先用三项低成本检查判断问题是否存在。

平衡正确答案位置

题库中的正确答案应在各位置近似均衡，避免数据分布本身制造偏差。

循环置换一小批题目

把同一题的选项轮换多次，观察语义答案是否稳定，并统计每个位置被选中的频率。

同时保存语义答案与选项 ID

不要只让模型返回 A。要求它输出所选内容、判断理由和最终 ID，便于区分知识错误与映射错误。

这三步不能完全消除偏见，但能快速发现固定顺序评测是否可信。

随后，系统再通过严格文本匹配或语义相似度，将答案映射回原选项。

这种方式既能减少字母线索，也能保留审计信息；但语义重述本身可能不稳定，当候选含义接近时，还会引入新的映射错误。

模型自报置信度通常没有校准，不能直接理解为真实概率。

四、PriDe：估计并扣除选项先验

PriDe 的核心思路，是把观测到的选项概率拆成「题目内容」和「选项 ID 先验」两部分。

简化后的工程流程：

  1. 从同分布测试题中抽取一小部分校准集；
  2. 对校准题多次置换选项内容；
  3. 估计模型对 A/B/C/D 的先验概率；
  4. 对剩余题目的原始概率进行先验校正；
  5. 同时报告校正前和校正后的成绩。

五、SCOPE：在题库排布阶段对抗偏好

SCOPE 则从选项放置的角度降低位置偏差，其思路可以概括为：

  1. 计算正确答案与干扰项之间的语义相似度；
  2. 找到最容易混淆的干扰项；
  3. 根据已测得的位置偏好进行随机或反偏放置；
  4. 减少显式字母线索；
  5. 将模型语义答案映射回原选项。

需要警惕的是，如果永远不把正确答案放在首位，同样会制造新的分布偏差。更稳妥的做法，是平衡位置、随机化排列，或根据已经测得的先验进行反向加权。

六、我采用的分层评测流程

层级 主要措施 目的
输入层 平衡或随机排布、去掉字母 减少位置和标签线索
作答层 逐项判断、语义答案、理由 保留可审计输出
校正层 PriDe 或置换频率 抵消剩余选项先验
映射层 严格匹配与语义复核 避免答案还原错误
统计层 多随机种子、置信区间 衡量结果稳定性

七、报告中应该包含哪些结果

  • 原始准确率与校正后准确率；
  • 各位置作为正确答案时的准确率；
  • 模型对各位置的选择率；
  • 同一道题不同排列的一致率；
  • 语义答案与字母答案不一致的比例；
  • 知识错误、位置错误和映射错误的数量；
  • 模型、Prompt、温度、随机种子和题库版本；
  • 校准集大小、置换方式和额外推理成本。

一旦模型版本、Prompt 或输出模板发生变化，都应重新测量位置先验。

八、这套方法的边界

  • PriDe 依赖可比较的选项概率或可靠近似；
  • 文本答案有时比首 token 概率更稳定，两者应分别检查；
  • 语义映射器本身也会引入误差；
  • 使用正确答案指导选项放置只适用于离线评测；
  • 选择题稳定不代表模型具备真实场景能力；
  • 抗偏后的高分仍需结合开放问答和任务评测解释。
